# Robot Programming: Path Smoothing Algorithms

## Overview

This project implements two different **path smoothing algorithms** designed to optimize paths generated by motion planners.
The project questions are contained in [2_Fragestellungen.md](2_Fragestellungen.md).

## Project Architecture

- **Smoothing methods**
The implementation of the smoothing methods follows a **base class pattern**:

   - [SmootherBase.py](SmootherBase.py): Abstract base class with shared functionality
   - [SmoothBG.py](SmoothBG.py): Deterministic smoothing using Bechthold-Glavina algorithm
   - [SmoothRandom.py](SmoothRandom.py): Stochastic smoothing through random sampling

- **Benchmark Notebooks**: The notebooks run the planners, apply both smoothing methods, and display visualizations/animations of planned and smoothed paths:
  - [Benchmark_Smoothing_Kin_2DoF.ipynb](Benchmark_Smoothing_Kin_2DoF.ipynb) 2-DoF planar manipulator benchmarks and animations.
  - [Benchmark_Smoothing_Kin_3DoF.ipynb](Benchmark_Smoothing_Kin_3DoF.ipynb) 3-DoF planar manipulator benchmarks and animations.
  - [Benchmark_Smoothing_PointRobot.ipynb](Benchmark_Smoothing_PointRobot.ipynb) point-robot benchmarks (e.g., trap, maze) with visualization.
  - [Benchmark_Smoothing_ShapeRobot.ipynb](Benchmark_Smoothing_ShapeRobot.ipynb) shape-robot benchmarks (e.g., trap, maze) with visualization.

- **Benchmark Functions**: Supporting modules for planning and evaluation:
  - [planner_config.py](planner_config.py) — Configurations for BasicPRM, VisibilityPRM, and LazyPRM planners.
  - [planning.py](planning.py) — Main function orchestrating planning and smoothing for all benchmark tasks and planners.
  - [ResultCollection.py](ResultCollection.py) — Container class collecting results (planned path, smoothed paths, graphs, performance metrics) for each benchmark run.
  - [diagram.py](diagram.py) — Generates comparison diagrams (path length, roadmap size, computation time) and iteration plots for smoothing progress.

## 1. SmootherBase.py – Base Class

### Purpose
Provides shared functionality and visualization tools for all smoothing algorithms.

### Main Components

#### **Class `Angle`**
Specialized angle handling class for correct angle calculations:

- **Problem**: Near boundary angles (e.g., 330° → 15°), naive difference can lead to incorrect rotation directions
- **Solution**: Calculates shortest angle difference and respects robot boundary constraints
- **Example**: A robot at 330° should move to 15° → rotates 50° (counterclockwise), not 315°

#### **Class `SmootherBase`**
Stores central data:

| Attribute | Description |
|-----------|------------|
| `smoothed_path` | The smoothed path |
| `path_planner` | The original planner |
| `config` | Configuration parameters |
| `path_per_epoche` | Path after each iteration (for animations) |
| `smoothing_time` | Runtime of the algorithm |

#### **Visualization Methods**

1. **`visualize_smoothing()`**
   - Animates the smoothing process through all iterations
   - Shows progressive reduction of waypoints
   - Uses NetworkX for graph visualization

2. **`animate_path()`**
   - Side-by-side comparison: Original vs. smoothed path
   - Interpolates positions based on arc length
   - Synchronizes robot movement across both paths

3. **`simple_draw()`**
   - Draws obstacles, graph, and robot position
   - Helper function for animations

## 2. SmoothBG.py – Bechthold-Glavina Algorithm

### Concept
**Deterministic, corner-based smoothing**: The algorithm iteratively identifies and removes the "strongest" corners in the path.

### Algorithm Workflow

```
1. Calculate "corner stiffness" for each corner (i, i+1, i+2):
   
   edge = (||p_i - p_{i+1}|| + ||p_{i+1} - p_{i+2}||) / ||p_i - p_{i+2}||
   
   (Higher values = stronger corners)

2. Sort all corners by stiffness (descending)

3. For the strongest corner, attempt:
   a) Direct skip: Can we jump from p_i to p_{i+2}?
   b) If not: Deltree-skip with intermediate nodes

4. Repeat until max iterations reached or no more skippable corners
```

### Methods

#### **`smooth_path(path, planner, config, clean_up=False)`**
Main method with parameters:

| Parameter | Meaning |
|-----------|---------|
| `corner_threshold` | Min. corner stiffness to process (0 = all) |
| `epoches` | Max. number of iterations |
| `collision_intervals` | Collision check resolution |
| `max_deltree_depth` | Depth of intermediate steps |

**Returns**: Smoothed path + updated graph

#### **`try_direct_skip(start, goal)`**
Checks if a direct jump is collision-free:
- Interpolates linear path into `collision_intervals` steps
- Tests each point for collision
- Considers 3D configuration space (x, y, angle)

#### **`try_deltree_skip(start, goal, skip_node)`**
Fallback strategy for blocked direct jumps:
- Binary bisection: Creates intermediate nodes closer to skip_node
- Test depth up to `max_deltree_depth`
- **Iteration k**: Place new points at halfway distance
  ```
  new_start = start + (skip_node - start) / 2^k
  new_goal = skip_node + (goal - skip_node) / 2^k
  ```

### Special Features

- **Deterministic**: Same input → Same output
- **Guaranteed Collision-Free**: All intermediate steps checked
- **Angle-Aware**: Correct angle calculation for robots with orientation
- **Computationally Intensive**: O(n²) per iteration (all corner combinations)

## 3. SmoothRandom.py – Random-Based Smoothing

### Concept
**Stochastic smoothing through random shortcuts**: The algorithm randomly attempts to connect points along path edges.

### Algorithm Workflow

```
1. For each iteration (epoch):
   
   a) Place a random point on each edge
      (Interpolation with random parameter t ∈ [0,1])
   
   b) Randomly select two different points (u, v) with u < v
   
   c) Check if direct jump is collision-free
   
   d) If successful: Replace path segment u..v with shortcut

2. Repeat until max epochs reached
```

### Methods

#### **`smooth_path(config)`**
Main method with parameters:

| Parameter | Meaning |
|-----------|---------|
| `epoches` | Number of smoothing iterations |
| `collision_intervals` | Resolution for collision checking |

**Returns**: Smoothed path + updated graph

#### **`findRandomShortcut()`**
Core logic of a smoothing iteration:

1. **Place random points**: One point per edge using `randomPtOnEdge()`
2. **Select two points**: Random indices u, v with u ≠ v
3. **Collision check**: Tests line using `lineInCollision()`
4. **Update on success**: `insertAndConnectPointsOnEdges()` updates path

#### **`randomPtOnEdge(start_node, end_node)`**
Linear interpolation with random parameter. For 3D (with orientation): Additionally uses `interpAngle()` for correct angle interpolation

#### **`interpAngle(theta0, theta1, t)`**
Interpolates angle over shortest distance:
- Uses `Angle` class for correct boundary constraints
- Considers periodic angle space boundaries

#### **`insertAndConnectPointsOnEdges(random_edge_pts, u, v)`**
Updates path after successful shortcut:

- New nodes: `S1, S2, ...` (unique IDs)
- **Case distinction**:
  - If v = u+1 (adjacent): Replace single node
  - Otherwise: Replace entire segment u..v
- Adds graph nodes and edges

## Algorithm Comparison

| Aspect | Bechthold-Glavina | Random |
|--------|-------------------|--------|
| **Strategy** | Deterministic, corner-based | Stochastic, random-based |
| **Runtime** | O(n²) per iteration | O(1) per iteration |
| **Result Quality** | Consistently optimal (locally) | Variable, luck-dependent |
| **Runtime Predictable** | Yes, max `epoches` iterations | No, early-exit possible |
